# NIA vs Hermes Agent — Full Gap Audit

> Generated by 3 parallel audit agents reading actual source code across all 15 subsystems.
> Hermes Agent: ~152,000 LOC | NIA: ~22,000 LOC (7× smaller)

---

## P0 — Broken Right Now

### 1. `.env` loading — `~/.nia/.env` is NEVER loaded at startup
- `nia setup` writes API key to `~/.nia/.env`
- Doctor checks for `.env` and reports "found with provider configuration"
- **But nothing loads it into `os.environ`** — no `dotenv` import, no `env_loader.py`
- User runs `nia` → "no API key" error despite setup showing success
- **Fix:** Add `python-dotenv` dependency + load `~/.nia/.env` at CLI startup with `override=True`

### 2. Compaction cooldown persistence — silently no-ops
- `LLMCompactor.bind_session_state` calls `getattr(session_db, "record_compression_failure_cooldown", None)`
- `SessionDB` doesn't implement that method → returns `None` → cooldown is in-memory only
- Restarts lose the cooldown state

### 3. Compaction locks — table exists but no methods
- `compression_locks` table is in the schema
- No `try_acquire_compression_lock` / `release_compression_lock` methods
- Two processes can compact the same session simultaneously
